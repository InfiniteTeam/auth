OIDC & Integrations

The platform is a standards-compliant OAuth 2.0 / OpenID Connect provider built on oidc-provider with a Nest.js backend.

Issuer and discovery

  • Issuer: https://auth.inft.kr
  • Discovery: https://auth.inft.kr/.well-known/openid-configuration
  • JWKS: https://auth.inft.kr/.well-known/jwks.json
  • WebFinger: https://inft.kr/.well-known/webfinger (RFC 7033)

Authorization flow

  1. The consumer redirects the end user to the authorization endpoint with response_type=code, scope=openid profile email, a PKCE code_challenge (S256) and a nonce.
  2. The end user signs in via LDAP and approves the requested scopes on the consent screen (hosted on apps/www).
  3. The provider redirects back with an authorization code.
  4. The consumer exchanges the code at the token endpoint (client_secret_post or PKCE) and receives access_token, refresh_token and id_token.
  5. The consumer verifies the id_token against the JWKS (RS256 / ES256) and fetches the userinfo endpoint when profile claims are needed.

Tailscale custom OIDC client

The first consuming service is Tailscale (custom OIDC).

SettingValue
Redirect URIhttps://login.tailscale.com/a/oauth_response
Scopesopenid profile email

Tailscale is configured in its admin console with the issuer https://auth.inft.kr. The client credentials are seeded into the backend and recorded in TAILSCALE_CLIENT_SECRET.

Consumer SDK — @inftkr/auth-sdk

For services that want to integrate, use @inftkr/auth-sdk.

The SDK provides:

  • PKCE authorization flow (RFC 7636)
  • ID token verification against the provider's JWKS
  • Token refresh (refresh_token grant)
  • RP-Initiated Logout (OIDC RP-Initiated Logout 1.0)
  • Userinfo retrieval

See the API Reference for full details on every SDK member.

Integration with the shared client (@inftkr/auth-core)

First-party apps (backend services, Nest.js guards, React frontends) use @inftkr/auth-core instead of the SDK:

  • AuthApiClient — typed HTTP client for POST /api/v1/auth/ldap, DELETE /api/v1/session, etc.
  • SessionGuard / PermissionsGuard — server-side guards.
  • useSession / useSignIn / useSignOut — React hooks (consumed by apps/www).

Session API contract

MethodRouteDescription
