Deployment

Self-hosted deployment via Docker Compose, domain routing and Cloudflare Tunnel

Deployment

The platform is shipped as a self-hostable Docker Compose package in deploy/. It provisions PostgreSQL, lldap, the Nest.js backend, the Next.js frontend and an optional Cloudflare Tunnel.

See deploy/README.md for the complete manual.

Requirements

  • Docker Engine 24+ and Docker Compose v2
  • Two domains: auth.example.com (OIDC issuer, frontend, API) and example.com (WebFinger)

Quick start (interactive setup)

Follow the prompts for domain, admin password and Cloudflare Tunnel. The script generates a .env file and the tunnel assets.

cloudflared runs under the tunnel Compose profile so a fresh install starts cleanly even before the tunnel files have been generated.

Domain routing

When using cloudflared, the ingress map is defined locally in cloudflared/config.yml (locally-managed mode). The tunnel token is only needed at setup time to derive cloudflared/credentials.json.

Documentation hosting

The apps/docs static site (Fumadocs) is published from a GitHub Actions workflow (.github/workflows/docs.yml) that runs on every push to develop:

  1. pnpm run docs generates the package API artifacts (docs.api.json).
  2. apps/docs is built as a static export into apps/docs/out/.
  3. The output is pushed to the gh-pages branch (artifact storage).
  4. The same output is deployed to Cloudflare Pages.

Cloudflare Pages requires two repository secrets:

SecretPurpose
CLOUDFLARE_API_TOKENWrangler API token with Pages edit permission
CLOUDFLARE_ACCOUNT_IDCloudflare account ID for the Pages project

Troubleshooting

  • backend health check failing: run docker compose logs backend. Possibly a Prisma migration failure — verify postgres is healthy.
  • lldap login failing: the initial admin password is LLDAP_ADMIN_PASSWORD. The admin account must have an email (LLDAP_ADMIN_EMAIL); the backend resolves users by email.
  • Domain not reachable: without cloudflared the stack is only reachable on localhost.
